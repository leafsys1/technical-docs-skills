# 中文表达与版式

只调整可编辑的说明文字。代码、配置、URL、引用标识、标准定义、真实错误和用户指定字面量保持其技术含义与语法；不要用全局替换统一它们。

## 语体

- 使用正式、平实、直接的工程表述。动作写清对象，条件放在动作之前；需要明确责任时使用“实施人员”“测试人员”“客户端”等具体角色。
- 删除没有信息的背景铺垫、复述任务、客套、自问自答和文末重复总结。避免“轻松”“无缝”“全面赋能”等无法核对的承诺。
- “部署”“验证”“加载”“保存”等词直接说明动作，不用“进行相关操作”“实现能力提升”等空壳替代。
- 同一概念使用同一术语，不为词汇变化将一个对象轮换叫作平台、系统、方案。已有正式术语不按普通词表机械改写。
- 句子和段落按信息负担拆分，不设机械字数门槛。必要的条件、并发关系、否定范围和例外不能因“短句化”丢失。
- “必须”“禁止”“仅”对应真实技术约束、授权边界或明确项目规则；建议写明适用条件和取舍。保留有依据的不确定性，不把“可能”改成“必然”。

## 结构

- 首段说明文档适用任务和范围，不写写作计划。标题反映任务或主题，不加宣传性副标题、表情或聊天式注释。
- 默认一份文档一个主标题，层级连续；以二、三级标题为主，确有需要再加深。完整产品手册按项目编号规范组织，不强迫所有文档相同章数。
- 一个段落说明一个主题。有真实顺序的动作用编号；并列信息用列表；对照数据用表格。保留技术逻辑，不把有因果关系的句子拆成“机械三点”。
- 强调只用于关键对象和会影响操作的内容；风险提示放在相应操作之前。不要用整屏加粗或连续提示框代替正文。
- 引用和链接紧随它们支持的具体陈述，不能在移动段落时扩大引用的支持范围。

## 术语、数字与排版

- 项目或官方写法优先。首次出现的必要缩写解释一次；不机械给所有中文词添加英文括注。
- 中文正文用规范中文标点，默认使用“”引号；已有出版/项目规范可覆盖。英文句子和机器可读内容保留自身标点。
- 可见正文中，中英文和数字之间的空格保持统一；全角标点前后不额外加空格。留白修改不得进入代码、URL、路径、公式或标识符。
- 数字用半角，单位与指标定义准确。区分 GB/GiB、bit/Byte、百分比/百分点、总量/增量、平均值/分位数。
- 倍数与变化给出基准。例如“增至 2 倍”和“增加 2 倍”含义不同；“降低若干倍”应改成有明确基准的比例或前后值。
- 版本号、镜像 digest、提交、端口、ID 和配置数值不添加千分位。正文的大数和日期按项目规范处理，不改变其值。
- UI 名称与实际界面一致；命令、路径、参数和配置键使用行内代码。链接文字说明目标，不用“点击这里”或依赖版面位置的“见上文”。

## 避免为“去 AI 味”损伤文档

不把单个词、被动句、合理列表或规范技术术语判为错误。只在具体上下文中处理信息空泛、逻辑漂移、机械重复和格式残留。已经清楚、自然且准确的文字可以不改。

不添加虚构经历、第一人称感想、幽默、错字或不确定观点来制造“真人感”。不得承诺检测器分数，也不据行文判断作者身份。
