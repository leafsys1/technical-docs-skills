# 审查要点

按文档任务选用，审查结构不等于强制生成相同章节。先处理影响读者操作和判断的问题，再处理文字风格。

| 检查对象 | 需要寻找的证据或缺陷 | 处理原则 |
| --- | --- | --- |
| 适用组合 | 实际硬件/架构、模型修订、软件组合；是否把另一环境的结果搬来 | 关键条件缺失或不一致时不能宣称可复现 |
| 版本接口 | 参数定义、帮助、配置 schema、对应源码/测试 | 不凭经验猜默认值或兼容范围 |
| 执行位置 | 本机/远端/容器、用户、目录、变量继承 | 从新终端逐步走查，补足隐含状态 |
| 命令可复制性 | 提示符、引号、续行、占位符、缺失脚本/输入 | 区分实际命令、语法示意与输出；不擅自执行 |
| 服务与持久性 | 实例标识、就绪、启用、自启动作用域和实际恢复范围 | 临时服务、持久定义、已启用和重启已恢复分别陈述 |
| 结果判定 | 退出码、接口响应、业务断言、成功/失败边界 | 不用健康接口或端口监听替代业务验证 |
| 测试用例 | 前置条件、输入、步骤、预期、阈值、实际记录位置 | 测试计划不预填真实“通过”；失败处理明确 |
| 性能与最佳实践 | 基线、控制变量、负载、指标、波动和代价 | 不跨架构/配置外推，不把建议写成普遍最优 |
| 异常与回退 | 停止点、现象与判断、备份/基线实物、数据保留 | 备份不存在、回退会覆盖新数据或根因无依据均需指出 |
| 引用与表达 | 因果、条件、否定、数量、术语与支持来源 | 对照原文核查，不为自然表达降低准确性 |
| 成品格式 | 目标载体、渲染、代码/表格/图、附件与链接 | 源码检查不冒充导出文件或浏览器实际验收 |

## 关键缺陷示例

- 用 x86_64 的结果标为已验证其他架构，或从另一个框架复制未核实参数。
- 用作者当前 Shell 的环境变量而没有读者的初始化方式，或将用户级服务写成系统级服务。
- 参数、脚本、模型文件或回退基线无法定位，读者必须猜才能执行核心流程。
- 代码块含待替换槽位却称为可直接复制，或把手工动作写成系统会自动完成。
- 仅有 HTTP 200、服务 active 或 CI 记录，却写完整功能、外部访问或重启恢复已通过。
- 改写时删除“仅”“可能”“同时”“在……条件下”等限制，导致结论增强。
- 测试报告没有实际记录，却填入通过状态或性能数字。

缺陷是否阻断交付取决于任务目标和影响，不按命中词数或固定总分决定。

## 审查记录

重要问题保留：位置、事实依据、影响、严重程度、建议、修订后的复查结果。疑似凭据仅说明位置和类别，不复述值。

静态走查可检查依赖和逻辑，离线脚本可检查部分结构；实际部署、完整复现、外部链路及整机重启只有执行过才能记录为已验证。无法执行时在结论中明确未验证范围，不自动否定有充分依据的其他部分。

若由作者本人完成审查，称为自查；确实有独立执行者时才称为独立审查。修订后复核关键步骤，不自动重新运行无关的大规模实验。
